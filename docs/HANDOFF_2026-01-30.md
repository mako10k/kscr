## Current Hypothesis: Deferred dict resolution is missing

**Problem**: When method dictionary choice cannot be made at rewrite time (local binders/pattern vars), the compiler currently emits a *dict-lambda* (`\__dict_C -> ...`).
If such dict-lambdas flow into value positions and are later applied as if they were the underlying function/value, runtime sees functions/thunks where primitives/lists are expected, producing errors like:
- `++ expects List`
- `intToString expects Integer`

**Policy requirement**: compile-time fallback is basically forbidden. If the dict cannot be decided, preserve the constraint and defer resolution as late as possible (ideally until the method is executed); only then collapse to a default.

**Symptoms**:
- Functions with Num constraints fail at runtime with "unbound variable" errors for dict parameters
- Local bindings in `let` expressions don't receive or pass dictionary parameters
- `where` clauses have similar issues with dict parameter plumbing

## Key Issues Summary

### 1. Dict Passing in Let/Where (PRIMARY FOCUS)
- Local bindings with Num/Show/etc constraints don't receive dict parameters
- Call sites within let/where don't pass dicts to local constrained functions
- Need to track local scope and rewrite both binding definitions and call sites

### 2. Qualified Dict Names
- Instance dicts registered as `__dict_Prelude.Enum_Integer`
- Some resolution paths try unqualified variants `__dict_Enum`
- See lines 80-94 in `typeclass_dict_passing_common.rs` for ground_dicts handling

### 3. Transitive Import Aliases
- `import A as OM` works in entry module
- Fails when alias is used in imported module B, then B is imported
- Need to inject alias forwarders for transitive imports or rewrite references

### 4. Case Exhaustiveness with Qualified Imports
- Importing constructors qualified causes "non-exhaustive case" errors
- Exhaustiveness checker doesn't recognize qualified constructor names

### 5. Cross-Module Deriving
- Hardcoded `stdlib_derives_show/eq()` for Rational
- Need to extend for Maybe, Either, and other stdlib types
- Proper fix requires KSIF to carry deriving information
