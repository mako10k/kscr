## Goal
- Treat `Eq` and `Show` as ordinary stdlib typeclasses (not solver/runtime special cases).
- Allow user-defined overrides (`instance Show T where ...`) to coexist with `deriving (Eq, Show)`.
- Make `main` runnable even when inference leaves class constraints (apply dictionaries at the entrypoint).

## What Changed
### Stdlib
- Added `class Eq` / `class Show` in `stdlib/Prelude.ks`.
  - `Eq`: `eq`, `(==) = eq`, `(/=)` defined from `(==)`.
  - `Show`: `show :: a -> [Char]`, `toString = show`, `print` uses `toString`.
- Primitive instances route through stable primitives:
  - `__primEq` for structural equality
  - `__primShow` for structural pretty-printing

### Deriving expansion
- `deriving (Eq)` / `deriving (Show)` now expands into synthetic `instance` items during typechecking.
  - Generated methods call `__primEq` / `__primShow` (stable names).
- If a matching explicit instance already exists for the same `(class, head-type)`, synthetic instance generation is skipped.
  - This prevents `duplicate instance` when users override derived behavior.

### Entry point (`main`) class constraints
- If the inferred `main` type has remaining class constraints (e.g. `Show a => IO Unit` via `print`), the compiler rewrites the entry module:
  - renames the original binding, then applies required dictionaries so the exported `main` is an `IO _` action.

### Runtime / IR builtins
- Added stable runtime builtins: `__primEq`, `__primShow`.
- Adjusted runtime builtin-var resolution so `show/toString` and `==/!=` are only provided as fallback when the name is undefined.
  - This avoids trivially shadowing Prelude/user definitions.

## Verified
- `cargo build` succeeds.
- Typechecking the Prelude works and infers expected schemes for `print` / `toString`.

## Current Breakage (important)
### Repro
A minimal override still fails at runtime:

```kscr
module Main where
  import Prelude

  data Box = Box Integer deriving (Eq)

  instance Show Box where
    show = \b -> "CUSTOM"

  main = print (Box 1)
```

Command:
```sh
./target/debug/kscr run --ksif-rebuild /tmp/kscr_show_override_noderive.ks
```

Observed:
- Runtime error: `show/toString expects a printable value`

### Root-cause hint (from IR dump)
The lowered Prelude `print` currently uses the internal helper in this shape:
- `__toString __builtinShowDict __dict_Show x`

The runtime implementation for `__toString`/`__show` currently interprets the *first* argument as the instance dictionary.
That causes the builtin show printer to be applied to the *instance dictionary record* (which contains closures), leading to:
- attempting to show a closure → `show/toString expects a printable value`

This looks like an arity/argument-order mismatch in the `__toString` / `__show` builtin path.

## Next Steps
- Fix the runtime semantics for `__show` / `__toString` (and likely `__eq`) so it matches the compiler’s dict-passing convention.
  - Expected shape appears to be: `__toString <builtin-method-dict> <instance-dict> <value>`.
  - The builtin should fetch `show` from the *instance dict*, apply it to the builtin-method-dict, then apply it to the value.
- Add a regression test that asserts the override prints `CUSTOM`.
